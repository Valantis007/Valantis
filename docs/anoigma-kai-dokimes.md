# Domain, εμφάνιση, δοκιμές και άνοιγμα

Οδηγός βήμα-βήμα: πώς η ιστοσελίδα αποκτά το δικό σας domain, πώς αλλάζει η εμφάνιση, και πώς βεβαιώνεστε ότι **όλα** λειτουργούν (κάρτες, εγγυήσεις, επιστροφές χρημάτων, emails) **πριν** δεχτείτε πραγματικούς πελάτες.

Η βασική ιδέα: η ιστοσελίδα ανεβαίνει στο κανονικό σας domain **με δοκιμαστικές πληρωμές** (εμφανίζεται κόκκινη ένδειξη «ΔΟΚΙΜΑΣΤΙΚΗ ΛΕΙΤΟΥΡΓΙΑ» σε κάθε σελίδα). Τα δοκιμάζετε όλα με δοκιμαστικές κάρτες, σβήνετε τα δοκιμαστικά δεδομένα, βάζετε τα πραγματικά κλειδιά και ανοίγετε.

| Στάδιο | Τι γίνεται | Πληρωμές |
|---|---|---|
| 1. Στον υπολογιστή σας | Βλέπετε την ιστοσελίδα, βάζετε αυτοκίνητα και τιμές | Μόνο «πληρωμή στην παραλαβή» |
| 2. Online στο domain σας | Πλήρεις δοκιμές (ενότητα 5) | Δοκιμαστικές (Stripe test / Revolut Sandbox) |
| 3. Άνοιγμα | Διαγραφή δοκιμαστικών δεδομένων, πραγματικά κλειδιά | Πραγματικές |
| 4. Πρώτες εβδομάδες | Καθημερινός έλεγχος του πίνακα | Πραγματικές |

> **Σημαντικό:** ο Stripe **απαγορεύει** «δοκιμές» με πραγματικές κάρτες σε λειτουργία live (όροι χρήσης Stripe). Όλες οι δοκιμές γίνονται με τα δοκιμαστικά κλειδιά και τις δοκιμαστικές κάρτες της ενότητας 4.

## 0. Δοκιμές πριν αγοράσετε domain

### 0.1 Γιατί δεν βλέπω πού να βάλω αριθμό κάρτας;
Ο αριθμός κάρτας **δεν** μπαίνει ποτέ στη δική μας ιστοσελίδα: μπαίνει στη σελίδα πληρωμής του Stripe (ή του Revolut), όπου ο πελάτης μεταφέρεται μετά το κουμπί «Κράτηση με υποχρέωση πληρωμής». Έτσι η ιστοσελίδα δεν αγγίζει ποτέ στοιχεία καρτών (απαίτηση ασφαλείας PCI). Όσο **δεν** έχει ρυθμιστεί πάροχος πληρωμών, η επιλογή «Κάρτα online» δεν εμφανίζεται καθόλου και υπάρχει μόνο «Πληρωμή κατά την παραλαβή». Αν είστε συνδεδεμένοι ως διαχειριστής, η σελίδα κράτησης σάς το λέει με ένα μπλε μήνυμα που δεν το βλέπουν οι πελάτες.

### 0.2 Δοκιμή με κάρτα στον υπολογιστή σας (Stripe) — βήμα-βήμα
1. Φτιάξτε δωρεάν λογαριασμό στο https://dashboard.stripe.com/register. Για τις δοκιμές **δεν** χρειάζεται να δώσετε στοιχεία επιχείρησης ή τράπεζας.
2. Στο Stripe, πάνω δεξιά, ενεργοποιήστε το **Test mode** (ή «Sandbox»). Μετά: **Developers → API keys** → στο «Secret key» πατήστε «Reveal» και αντιγράψτε το (ξεκινά με `sk_test_`).
3. Στον φάκελο της ιστοσελίδας υπάρχει το αρχείο **`.env`** (δημιουργείται μόνο του την πρώτη φορά που ξεκινάτε με διπλό κλικ). Ανοίξτε το με το Σημειωματάριο (Windows: δεξί κλικ → «Άνοιγμα με» → Σημειωματάριο· Mac: TextEdit). Αν δεν το βλέπετε στα Windows: στην Εξερεύνηση αρχείων → Προβολή → «Κρυφά στοιχεία».
4. Βρείτε τη γραμμή `STRIPE_SECRET_KEY=` και επικολλήστε το κλειδί αμέσως μετά το `=`, χωρίς κενά: `STRIPE_SECRET_KEY=sk_test_51...`. Αποθηκεύστε.
5. Κλείστε την ιστοσελίδα (στο μαύρο παράθυρο: **Ctrl+C**, ή κλείστε το παράθυρο) και ξεκινήστε τη ξανά με διπλό κλικ. Πάνω σε κάθε σελίδα εμφανίζεται πλέον η κόκκινη ένδειξη **«ΔΟΚΙΜΑΣΤΙΚΗ ΛΕΙΤΟΥΡΓΙΑ»**.
6. Κάντε μια κράτηση: στο βήμα «Πληρωμή» διαλέξτε **«Κάρτα online»** → «Κράτηση με υποχρέωση πληρωμής». Ανοίγει η σελίδα του Stripe με πεδίο για κάρτα. Βάλτε `4242 4242 4242 4242`, οποιαδήποτε μελλοντική ημερομηνία (π.χ. `12/30`), CVC `123`, οποιοδήποτε όνομα.
7. Επιστρέφετε στην ιστοσελίδα και η κράτηση εμφανίζεται «Επιβεβαιωμένη». Στο Stripe (Test mode → Payments) βλέπετε την πληρωμή. Δοκιμάστε και τις υπόλοιπες κάρτες της ενότητας 4.1 (απόρριψη, 3D Secure κ.λπ.).
8. Τα webhooks (ειδοποιήσεις του Stripe) δεν φτάνουν στον υπολογιστή σας. Η ιστοσελίδα συγχρονίζεται μόνη της κάθε 5 λεπτά, οπότε όλα ολοκληρώνονται — απλώς με καθυστέρηση. Για άμεσα webhooks: εγκαταστήστε το [Stripe CLI](https://docs.stripe.com/stripe-cli) και τρέξτε `stripe listen --forward-to localhost:3000/webhooks/stripe` (βάλτε το `whsec_...` που εμφανίζει στο `STRIPE_WEBHOOK_SECRET`).

### 0.3 Emails χωρίς ρύθμιση email
Χωρίς SMTP τα emails δεν στέλνονται, αλλά **καταγράφονται**: **Διαχείριση → Έλεγχος συστήματος → Τελευταία emails → «Προβολή»** ανοίγει το email ακριβώς όπως θα το λάβει ο πελάτης (στη γλώσσα του, με τα συνημμένα του). Για πραγματική αποστολή, ενότητα 2.

### 0.4 Φωτογραφίες αυτοκινήτων
**Διαχείριση → Στόλος → «Λήψη ενδεικτικών φωτογραφιών»**: κατεβάζει από τη Wikipedia (Wikimedia Commons) μία φωτογραφία με ελεύθερη άδεια για κάθε αυτοκίνητο χωρίς δική σας φωτογραφία, με την υποχρεωτική αναφορά δημιουργού (κάτω από τη φωτογραφία στη σελίδα του αυτοκινήτου και στη σελίδα «Πηγές φωτογραφιών», με σύνδεσμο στο κάτω μέρος κάθε σελίδας). Είναι για να δείτε την εμφάνιση· πριν το άνοιγμα ανεβάστε φωτογραφίες των δικών σας αυτοκινήτων (επεξεργασία αυτοκινήτου → Φωτογραφία). Ιδανικά: οριζόντια λήψη 16:9 ή 4:3, από μπροστά-πλάγια, καθαρό φόντο, τουλάχιστον 1200 pixels πλάτος.

**Revolut:** το Revolut δεν επιστρέφει τον πελάτη σε διεύθυνση `localhost` και δεν στέλνει webhooks εκεί. Για πλήρη δοκιμή Revolut (και για να δοκιμάσετε από το κινητό σας) χρειάζεται διεύθυνση στο internet:

**Online χωρίς δικό σας domain:** στο Render η υπηρεσία παίρνει δωρεάν διεύθυνση της μορφής `https://to-onoma-sas.onrender.com`, με HTTPS. Βάλτε την ως `BASE_URL` και κάντε όλες τις δοκιμές της ενότητας 5. Όταν αγοράσετε domain, το προσθέτετε στην ίδια υπηρεσία (ενότητα 1) και αλλάζετε το `BASE_URL`. Στο δωρεάν πακέτο του Render η υπηρεσία «κοιμάται» όταν δεν χρησιμοποιείται και τα δεδομένα χάνονται σε επανεκκίνηση· για δοκιμές αρκεί, για πραγματική λειτουργία χρειάζεται πληρωμένο πακέτο με μόνιμο δίσκο.

## 1. Δικό σας domain

### 1.1 Αγορά domain
Για `.gr` χρειάζεστε καταχωρητή διαπιστευμένο από την ΕΕΤΤ (π.χ. papaki.gr, top.host, dnhost.gr). Προτιμήστε σύντομο όνομα και αγοράστε, αν θέλετε, και το `.com`. Θα χρησιμοποιήσουμε τη μορφή `www.to-domain-sas.gr` ως κύρια διεύθυνση.

### 1.2 Σύνδεση του domain με τον server

**Αν φιλοξενείτε στο Render**
1. Render → η υπηρεσία σας → **Settings → Custom Domains → Add**: προσθέστε `www.to-domain-sas.gr` και `to-domain-sas.gr`.
2. Στον καταχωρητή (διαχείριση DNS):
   - `www` → εγγραφή **CNAME** προς τη διεύθυνση `κάτι.onrender.com` που σας δείχνει το Render.
   - `@` (σκέτο domain) → εγγραφή **A** προς τη διεύθυνση IP που σας δείχνει το Render (ή ALIAS/ANAME, αν το υποστηρίζει ο καταχωρητής).
   - Διαγράψτε τυχόν εγγραφές **AAAA** για το domain (το Render δεν υποστηρίζει IPv6).
3. Περιμένετε από λίγα λεπτά έως λίγες ώρες. Το Render εκδίδει αυτόματα πιστοποιητικό HTTPS («Verified» / «Certificate issued»).

Οδηγίες Render: https://render.com/docs/custom-domains και https://render.com/docs/configure-other-dns

**Αν φιλοξενείτε σε δικό σας server (VPS) με Docker και Caddy**
1. Στον καταχωρητή: `@` και `www` → εγγραφές **A** προς τη διεύθυνση IP του server.
2. Στο αρχείο `Caddyfile`:
   ```
   to-domain-sas.gr {
       redir https://www.to-domain-sas.gr{uri} permanent
   }
   www.to-domain-sas.gr {
       reverse_proxy localhost:3000
   }
   ```
   Το Caddy βγάζει μόνο του πιστοποιητικό HTTPS μόλις το domain δείξει στον server.

### 1.3 Μετά τη σύνδεση (υποχρεωτικά)
- [ ] Στο `.env`: `BASE_URL=https://www.to-domain-sas.gr` (ακριβώς έτσι, χωρίς `/` στο τέλος) και `TRUST_PROXY=1`. Επανεκκίνηση.
- [ ] **Διαχείριση → Έλεγχος συστήματος**: «Διεύθυνση» και «Η σύνδεση είναι ασφαλής (HTTPS)» με πράσινο.
- [ ] Πληρωμές: το webhook πρέπει να δείχνει στη νέα διεύθυνση:
  - Stripe → Developers → Webhooks: `https://www.to-domain-sas.gr/webhooks/stripe` (νέο signing secret στο `STRIPE_WEBHOOK_SECRET`).
  - Revolut: τρέξτε ξανά `npm run revolut:webhook` και βάλτε το νέο `REVOLUT_WEBHOOK_SECRET`.
  - Επιβεβαίωση: **Έλεγχος συστήματος → «Έλεγχος σύνδεσης & webhook»** → «όλα εντάξει».
- [ ] Email από το domain σας (ενότητα 2).

## 2. Emails

### 2.1 Ρύθμιση
Χρειάζεστε υπηρεσία αποστολής email για το domain σας, π.χ. **Google Workspace**, **Microsoft 365**, ή υπηρεσία αποστολής όπως **Brevo**, **Mailgun**, **Amazon SES**. Από αυτήν παίρνετε τα στοιχεία SMTP:

```
SMTP_HOST=...
SMTP_PORT=587          (ή 465 με SMTP_SECURE=true)
SMTP_USER=...
SMTP_PASS=...
MAIL_FROM="Το Όνομά Σας <info@to-domain-sas.gr>"
ADMIN_NOTIFY_EMAIL=info@to-domain-sas.gr
```

**Για δοκιμές, πριν το domain (Gmail):** μπορείτε να στέλνετε από έναν λογαριασμό Gmail. Ενεργοποιήστε την «Επαλήθευση σε 2 βήματα» στον λογαριασμό Google, φτιάξτε **Κωδικό εφαρμογής** στο https://myaccount.google.com/apppasswords και βάλτε:
```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=to-gmail-sas@gmail.com
SMTP_PASS=ο κωδικός εφαρμογής των 16 γραμμάτων (χωρίς κενά)
MAIL_FROM="Rent a Car <to-gmail-sas@gmail.com>"
```
Μην το χρησιμοποιήσετε για την πραγματική λειτουργία: το Gmail έχει όριο ~500 emails/ημέρα και τα emails από @gmail.com για επιχείρηση φαίνονται λιγότερο αξιόπιστα. Με το domain σας, περάστε σε μία από τις υπηρεσίες παραπάνω (π.χ. Brevo: δωρεάν έως 300 emails/ημέρα).

Στο DNS του domain προσθέστε τις εγγραφές **SPF**, **DKIM** και **DMARC** που σας δίνει η υπηρεσία email. Χωρίς αυτές τα emails καταλήγουν στα ανεπιθύμητα (spam).

### 2.2 Έλεγχος
1. **Έλεγχος συστήματος → Δοκιμαστικό email**: στείλτε σε ένα Gmail και σε ένα Outlook/Hotmail. Πρέπει να έρθει στα **εισερχόμενα**, όχι στα ανεπιθύμητα.
2. Πηγαίνετε στο https://www.mail-tester.com, αντιγράψτε τη διεύθυνση που δίνει, στείλτε εκεί δοκιμαστικό email και δείτε τη βαθμολογία. Στόχος: **9/10 ή περισσότερο**. Η σελίδα εξηγεί τι λείπει (συνήθως SPF/DKIM).
3. Ο πίνακας «Τελευταία emails» στον Έλεγχο συστήματος δείχνει κάθε email που στάλθηκε ή απέτυχε.

### 2.3 Ποια emails στέλνει η ιστοσελίδα
| Email | Πότε | Παραλήπτης |
|---|---|---|
| Επιβεβαίωση κράτησης (με τους όρους συνημμένους) | Επιβεβαίωση κράτησης / «Επαναποστολή» από τη διαχείριση | Πελάτης |
| Νέα κράτηση | Κάθε νέα επιβεβαιωμένη κράτηση | Γραφείο |
| Ακύρωση κράτησης | Ακύρωση από πελάτη ή γραφείο | Πελάτης |
| Επιστροφή πληρωμής | Διπλή ή καθυστερημένη πληρωμή που επιστράφηκε αυτόματα | Πελάτης |
| Σύνδεσμος εγγύησης | Το γραφείο στέλνει σύνδεσμο εγγύησης | Πελάτης |
| Δέσμευση εγγύησης | Ο πελάτης ενέκρινε την εγγύηση online | Πελάτης |
| Εκκαθάριση / αποδέσμευση εγγύησης | Κλείσιμο εγγύησης | Πελάτης |
| Χρέωση μετά την επιστροφή / Χρέωση για αποδοχή | Καταχώρηση χρέωσης | Πελάτης |
| Αποδοχή / αμφισβήτηση χρέωσης | Απάντηση του πελάτη | Γραφείο |
| Ειδοποιήσεις εγγύησης και επιστροφών χρημάτων | Αποτυχίες, λήξεις, ενέργειες που χρειάζονται | Γραφείο |
| Καλώς ήρθατε / Επαναφορά κωδικού | Εγγραφή / «Ξέχασα τον κωδικό» | Πελάτης |
| Λάβαμε το μήνυμά σας + Νέο μήνυμα | Φόρμα επικοινωνίας | Πελάτης + γραφείο |

## 3. Εμφάνιση της ιστοσελίδας

Όλα αλλάζουν χωρίς να επηρεάζεται η λειτουργία. Δοκιμάστε πρώτα στον υπολογιστή σας (στάδιο 1).

| Τι | Πού |
|---|---|
| Χρώματα | `public/css/style.css`, στην αρχή: `--brand` (κύριο χρώμα, κουμπιά), `--brand-dark`, `--accent` (δευτερεύον) κ.λπ. |
| Όνομα επιχείρησης στην κεφαλίδα | `COMPANY_NAME` στο `.env` |
| Λογότυπο | `views/partials/header.ejs` (εικονίδιο αυτοκινήτου + όνομα) — μπορεί να αντικατασταθεί με εικόνα |
| Εικονίδιο καρτέλας | `public/img/favicon.svg` |
| Φωτογραφίες αυτοκινήτων | Διαχείριση → Στόλος → επεξεργασία αυτοκινήτου (ή «Λήψη ενδεικτικών φωτογραφιών», ενότητα 0.4) |
| Κείμενα αρχικής σελίδας | `views/pages/home.ejs` |
| Συχνές ερωτήσεις | `views/pages/faq.ejs` |
| Ωράριο, κανόνες, τιμές | `.env` και Διαχείριση (σημεία, πρόσθετα, εποχικές τιμές) |

**Προσοχή όταν αλλάζετε κείμενα:** μην αλλάξετε τα νομικά κείμενα (όροι, πολιτική απορρήτου, ενημέρωση πριν την κράτηση, κουμπί «Κράτηση με υποχρέωση πληρωμής») χωρίς τον δικηγόρο. Αν αλλάξουν οι όροι, αλλάξτε το `TERMS_VERSION`.

Μετά από αλλαγή εμφάνισης: ελέγξτε σε κινητό και υπολογιστή, και ότι το κείμενο διαβάζεται καλά πάνω στα νέα χρώματα.

## 4. Δοκιμαστικές πληρωμές

Στη δοκιμαστική λειτουργία εμφανίζεται κόκκινη ένδειξη σε κάθε σελίδα. **Καμία πραγματική χρέωση δεν γίνεται.**

### 4.1 Stripe (test mode)
1. Stripe Dashboard → ενεργοποιήστε **Test mode** → Developers → API keys → αντιγράψτε το `sk_test_...` στο `STRIPE_SECRET_KEY`.
2. Developers → Webhooks (σε test mode) → endpoint `https://www.to-domain-sas.gr/webhooks/stripe` με τα γεγονότα του README → signing secret στο `STRIPE_WEBHOOK_SECRET`.
3. **Έλεγχος συστήματος → Έλεγχος σύνδεσης & webhook** → «όλα εντάξει».

Δοκιμαστικές κάρτες (οποιαδήποτε μελλοντική ημερομηνία λήξης, οποιοδήποτε CVC, οποιοσδήποτε ΤΚ):

| Κάρτα | Αποτέλεσμα |
|---|---|
| `4242 4242 4242 4242` | Visa πιστωτική — επιτυχία |
| `4000 0027 6000 3184` | Ζητά επιβεβαίωση 3D Secure (εμφανίζεται παράθυρο έγκρισης) |
| `4000 0000 0000 9995` | Απόρριψη: ανεπαρκές υπόλοιπο |
| `4000 0000 0000 0002` | Απόρριψη κάρτας |
| `4000 0566 5566 5556` | Visa **χρεωστική** — πρέπει να **απορριφθεί για την εγγύηση** |
| `5105 1051 0510 5100` | Mastercard **προπληρωμένη** — πρέπει να **απορριφθεί για την εγγύηση** |

Πλήρης λίστα: https://docs.stripe.com/testing

### 4.2 Revolut (Sandbox)
1. Δημιουργήστε **ξεχωριστό** λογαριασμό Revolut Business Sandbox (https://sandbox-business.revolut.com) — δεν συνδέεται με τον πραγματικό.
2. Sandbox → Merchant API → secret key στο `REVOLUT_SECRET_KEY` και `REVOLUT_SANDBOX=true`.
3. `npm run revolut:webhook` → `REVOLUT_WEBHOOK_SECRET`.
4. **Έλεγχος συστήματος → Έλεγχος σύνδεσης & webhook**.

Δοκιμαστικές κάρτες Sandbox (οποιοδήποτε CVV, μελλοντική λήξη):

| Κάρτα | Αποτέλεσμα |
|---|---|
| `4929 4205 7359 5709` | Visa — επιτυχία |
| `5281 4388 0180 4148` | Mastercard — επιτυχία |
| `4929 5736 3812 5985` | Απόρριψη: ανεπαρκές υπόλοιπο (μόνο σε πληρωμή, όχι σε εγγύηση) |

Περιορισμοί του Sandbox: στις **εγγυήσεις** (προέγκριση) όλες οι κάρτες, ακόμη και οι κάρτες σφάλματος, εγκρίνονται. Ο έλεγχος «μόνο πιστωτικές» εξαρτάται από τον τύπο που δηλώνει η κάρτα — αν μια δοκιμαστική κάρτα του Sandbox δηλώνεται χρεωστική, η εγγύηση απορρίπτεται (αυτό δείχνει ότι ο έλεγχος δουλεύει· δοκιμάστε την άλλη κάρτα). Τρέχουσα λίστα: https://developer.revolut.com/docs/guides/merchant/test-and-go-live/testing/test-cards

### 4.3 POS του γραφείου
Ρωτήστε την τράπεζα πώς γίνεται **προέγκριση (pre-authorisation)**, **ολοκλήρωση προέγκρισης** με μικρότερο ποσό και **ακύρωση προέγκρισης** στο τερματικό σας, και αν μπορείτε να κάνετε μια δοκιμή. Βεβαιωθείτε ότι το POS είναι διασυνδεδεμένο με την ταμειακή/πάροχο τιμολόγησης (υποχρέωση ΑΑΔΕ).

## 5. Σενάρια δοκιμών

Κάντε τα με δοκιμαστικές πληρωμές, στο κανονικό domain, από **κινητό και υπολογιστή**. Χρησιμοποιήστε ένα δικό σας email ως «πελάτη» και ελέγχετε κάθε φορά τα emails.

Συμβουλή: κάντε μια δοκιμαστική κράτηση με παραλαβή **σε 3–4 ώρες** για τα σενάρια παράδοσης/εγγύησης, και μία **σε 1 εβδομάδα** για τις ακυρώσεις.

### Α. Κράτηση και πληρωμή
- [ ] **Αναζήτηση**: ημερομηνίες, σημείο παραλαβής → εμφανίζονται μόνο διαθέσιμα αυτοκίνητα με την τελική τιμή.
- [ ] **Κράτηση με πληρωμή στην παραλαβή** → σελίδα επιβεβαίωσης → email επιβεβαίωσης με **συνημμένους όρους** → email «Νέα κράτηση» στο γραφείο.
- [ ] **Κράτηση με κάρτα** (`4242…`) → σελίδα πληρωμής του παρόχου → επιστροφή στην ιστοσελίδα → «Επιβεβαιωμένη» → email.
- [ ] **Κάρτα με 3D Secure** (`4000 0027 6000 3184`) → έγκριση στο παράθυρο → επιβεβαίωση.
- [ ] **Απορριφθείσα κάρτα** (`…0002`) → μήνυμα σφάλματος στη σελίδα πληρωμής, η κράτηση δεν επιβεβαιώνεται.
- [ ] **Κλείσιμο του browser αμέσως μετά την πληρωμή** (πριν επιστρέψει στην ιστοσελίδα) → σε 1–2 λεπτά η κράτηση εμφανίζεται «Επιβεβαιωμένη» στη διαχείριση (δουλεύει το webhook).
- [ ] **Εγκατάλειψη πληρωμής** (μπαίνετε στη σελίδα πληρωμής και τη κλείνετε) → μετά από ~35 λεπτά η κράτηση «Έληξε» και το αυτοκίνητο είναι ξανά διαθέσιμο.
- [ ] **Δεν γίνεται διπλή κράτηση**: προσπαθήστε να κλείσετε το ίδιο αυτοκίνητο τις ίδιες ημέρες → δεν εμφανίζεται διαθέσιμο.
- [ ] **Πρόσθετα**: με παιδικό κάθισμα ζητούνται ηλικία/βάρος παιδιού· με «Πλήρη Απαλλαγή» η απαλλαγή γίνεται 0 €.
- [ ] **Τιμολόγιο**: λάθος ΑΦΜ απορρίπτεται, σωστός γίνεται δεκτός.

### Β. «Η κράτησή μου» και ακυρώσεις
- [ ] «Η κράτησή μου» με κωδικό + email → εμφανίζεται η κράτηση· με λάθος email όχι.
- [ ] **Εκτύπωση** κράτησης.
- [ ] **Δωρεάν ακύρωση** (κράτηση με κάρτα, παραλαβή σε >48 ώρες) → email ακύρωσης → η επιστροφή φαίνεται στο Stripe/Revolut dashboard (Payments → Refunds).
- [ ] **Καθυστερημένη ακύρωση** (παραλαβή σε <48 ώρες) → ζητείται αποδοχή της χρέωσης → επιστρέφεται μόνο η διαφορά.
- [ ] **Ακύρωση από τη διαχείριση** με μερική επιστροφή.

### Γ. Εγγύηση
- [ ] **Online με QR**: Διαχείριση → κράτηση → «Δέσμευση εγγύησης → Online» → σκανάρετε το QR με το κινητό → αποδοχή → πληρωμή με `4242…` → «Δεσμευμένη» + email στον πελάτη.
- [ ] **Χρεωστική κάρτα** (`4000 0566 5566 5556`) στην εγγύηση → απορρίπτεται, μήνυμα «η κάρτα δεν είναι πιστωτική», η δέσμευση ακυρώνεται.
- [ ] **POS**: καταχώρηση με αριθμό έγκρισης.
- [ ] Παράδοση **χωρίς** εγγύηση δεν επιτρέπεται (εκτός αν το επιλέξετε ρητά).
- [ ] **Επιστροφή χωρίς χρεώσεις** → «Εκκαθάριση» → πλήρης αποδέσμευση → email. Στο Stripe/Revolut dashboard η δέσμευση εμφανίζεται «Canceled/Cancelled».
- [ ] **Επιστροφή με χρέωση καυσίμου** (π.χ. 30 €) → email «Χρέωση μετά την επιστροφή» → «Εκκαθάριση» → παρακρατούνται 30 €, τα υπόλοιπα αποδεσμεύονται → στο dashboard «captured 30 €».
- [ ] **Ζημιά**: καταχώρηση με τεκμηρίωση → email «Χρέωση για αποδοχή» → ο «πελάτης» την **αποδέχεται** από τη σελίδα της κράτησης (και σε δεύτερη δοκιμή την **αμφισβητεί**) → email στο γραφείο.
- [ ] Ζημιά πάνω από την απαλλαγή απορρίπτεται χωρίς αναφορά εξαίρεσης.
- [ ] **Υπόλοιπο που δεν καλύφθηκε** από την εγγύηση → ο πελάτης βλέπει κουμπί «Πληρωμή» στη σελίδα της κράτησης → πληρώνει.
- [ ] **Ακύρωση κράτησης με δεσμευμένη εγγύηση** → η εγγύηση αποδεσμεύεται αυτόματα.
- [ ] **Αυτόματη αποδέσμευση**: online εγγύηση χωρίς χρεώσεις αποδεσμεύεται μόνη της 48 ώρες μετά την επιστροφή.

### Δ. Διαχείριση
- [ ] Πίνακας ελέγχου: σημερινές παραδόσεις/επιστροφές, «Χρειάζονται ενέργεια», «Παραστατικά προς έκδοση».
- [ ] Παράδοση (χιλιόμετρα, είσπραξη) → Επιστροφή.
- [ ] Καταχώρηση ΜΑΡΚ σε παραστατικό → φεύγει από τη λίστα.
- [ ] Στόλος: νέο αυτοκίνητο με φωτογραφία, απαλλαγή, εγγύηση· δέσμευση για σέρβις → δεν εμφανίζεται διαθέσιμο εκείνες τις ημέρες.
- [ ] Σημεία, πρόσθετα, εποχικές τιμές → η τιμή στην αναζήτηση αλλάζει ανάλογα.
- [ ] Νέος διαχειριστής από «Χρήστες».

### Ε. Λογαριασμοί, φόρμες, νομικές σελίδες
- [ ] Εγγραφή → email «Καλώς ήρθατε» → σύνδεση (με και χωρίς «Να με θυμάσαι»).
- [ ] «Ξέχασα τον κωδικό» → email → νέος κωδικός.
- [ ] Λογαριασμός → «Λήψη δεδομένων» → «Διαγραφή λογαριασμού».
- [ ] Φόρμα επικοινωνίας με «Παράπονο» → email «Λάβαμε το μήνυμά σας» → εμφανίζεται στα Μηνύματα με σήμανση.
- [ ] Footer: σωστά ΑΦΜ, ΓΕΜΗ, ΜΗΤΕ, διεύθυνση· σελίδες Όροι, Απόρρητο, Στοιχεία εταιρείας, Παράπονα.

### ΣΤ. Τεχνικά

- [ ] Αντίγραφο ασφαλείας: γίνεται καθημερινά, και **δοκιμάστε μία επαναφορά** σε άλλο φάκελο.

## 6. Άνοιγμα

1. [ ] Ολοκληρώθηκαν τα βήματα με λογιστή, δικηγόρο, ασφαλιστική (README → «Λίστα ελέγχου πριν το άνοιγμα»).
2. [ ] Σταματήστε την εφαρμογή και σβήστε τα δοκιμαστικά δεδομένα:
   ```
   npm run clear-test-data            (δείχνει τι θα διαγραφεί)
   npm run clear-test-data -- --yes   (διαγράφει — κρατά αντίγραφο της βάσης)
   ```
   Μένουν αυτοκίνητα, σημεία, πρόσθετα, εποχικές τιμές και διαχειριστές.
3. [ ] Στο `.env` βάλτε τα **πραγματικά** κλειδιά:
   - Stripe: `sk_live_...` και το signing secret του **live** webhook (το webhook δημιουργείται ξανά σε live mode).
   - Revolut: production secret key, `REVOLUT_SANDBOX=false`, και ξανά `npm run revolut:webhook`.
4. [ ] `NODE_ENV=production`, επανεκκίνηση.
5. [ ] **Έλεγχος συστήματος**: όλα πράσινα, «ΠΡΑΓΜΑΤΙΚΕΣ πληρωμές», η κόκκινη ένδειξη δοκιμαστικής λειτουργίας **έχει φύγει**.
6. [ ] Δοκιμαστικό email ξανά.
7. [ ] Η πρώτη πραγματική κράτηση (π.χ. γνωστού σας που θα νοικιάσει πράγματι): παρακολουθήστε την από την αρχή ως το τέλος — πληρωμή, email, εγγύηση, εκκαθάριση, παραστατικό.

## 7. Μετά το άνοιγμα

- **Κάθε μέρα**: Πίνακας ελέγχου → «Χρειάζονται ενέργεια» (εγγυήσεις, χρεώσεις, επιστροφές) και «Παραστατικά προς έκδοση».
- **Κάθε εβδομάδα**: Έλεγχος συστήματος, Μηνύματα, αντίγραφα ασφαλείας.
- **Παρακολούθηση λειτουργίας**: δωρεάν υπηρεσία όπως UptimeRobot που ελέγχει κάθε 5 λεπτά τη διεύθυνση `https://www.to-domain-sas.gr/healthz` και σας στέλνει email/SMS αν η ιστοσελίδα πέσει.
- **Stripe/Revolut dashboard**: ελέγχετε περιοδικά ότι οι πληρωμές και οι επιστροφές συμφωνούν με τη διαχείριση· απαντάτε αμέσως σε αμφισβητήσεις (disputes/chargebacks) με τα στοιχεία της κράτησης (όροι, έκδοση όρων, συναίνεση στη χρέωση).
- **Ενημερώσεις**: κάθε αλλαγή στον κώδικα δοκιμάζεται πρώτα στον υπολογιστή σας ή σε δοκιμαστικό αντίγραφο, με `npm test`.
